# i18n 多语言协议 — 逐步约束（供任意智能体粘贴）

> 与 `SKILL.md` 同源；本文件可单独复制到 ChatGPT / Claude / 其他 IDE Agent 的「指令 / 项目规则」中。

---

## 任务模型

- **仓库根目录**内存在 `language-package/en/`（主语言）与多个 `language-package/<code>/`（目标语言）。
- **主语言文件**：`language-package/en/` 下唯一**不以** `i18n-` 开头的 `.json`（如 `en_英语.json`）。
- **目标语言代码 `<code>`**：与**目录名**一致（如 `zh`、`de`、`ja`），不是文件名里的别名。
- **长度 / 语气**：只认**用户本句对话**中的自然语言要求；**不**从仓库读 `i18n-length-rules.json`（项目不维护该文件）。

---

## 全局硬约束（全程有效）

| 类型 | 约束 |
|------|------|
| MUST | 占位符与英文模板**逐字一致**：`{name}`、`{0}`、`%s`、`{{x}}` 等不译、不改、不删。 |
| MUST | JSON 合法；写回时**保留该文件原有缩进**（Tab 或空格与现文件一致）。 |
| MUST NOT | 把「仅输出 batch、让用户自己合并」当默认交付；**除非**用户明确说只要草稿或无写权限。 |
| MUST NOT | 编造不存在的 key；所有 key 须先出现于主语言 JSON。 |
| SHOULD | UI 文案简洁；用户未提字数时仍避免过长。 |

---

## 阶段 0 — 解析用户意图

**输入**：用户消息（可能含英文键值、文件路径、长度要求、目标语言范围）。

**动作**：

1. 提取：**涉及 key 列表**（若用户给的是 JSON 对象则取全部 key）。
2. 判定 **Scope**：`FULL`（默认：除 `en` 外**所有**有业务 JSON 的目录）或 `SUBSET`（用户点名如「只要 zh、de」）。
3. 提取 **Policy**：用户关于字数（如「某 key ≤20，按 JavaScript `String.length`」）、语气、专有名词大小写等；无则 Policy 为空。

**完成判据**：能用一句话复述「翻哪些 key → 哪些语言 → 哪些额外约束」。

---

## 阶段 1 — 读取主语言（Source of Truth）

**动作**：

1. 定位并读取主语言 JSON（路径规则见上）。
2. 若用户给出了新的英文键值对象：将相同 **key → 英文 value** **合并**进主语言 JSON（新增或覆盖 value）；值须为合法 JSON 字符串。

**完成判据**：主语言 JSON 中已包含本任务所需的全部 key 与最新英文。

---

## 阶段 2 — 结构对齐（Key 集合一致）

**首选**：在仓库根执行 `npm run i18n:sync-keys`（或 `node translate-json.js`）。  
**等价手工**：对每个 `language-package/<code>/`（`<code> !== en`）的业务 JSON：

- 主语言有的 key、目标缺少 → 补 `"key": ""`。
- 主语言已删的 key、目标仍有多余 → **删除**该 key。

**完成判据**：每个目标语言 JSON 的 key 集合与主语言**完全一致**（可先空字符串，再阶段 4 填译）。

**若无法执行命令**：本阶段必须手工完成，**不得**跳过。

---

## 阶段 3 — 枚举目标语言

**动作**：

1. 列出 `language-package` 下子目录，排除 `en`。
2. 保留其中**存在**符合「业务 JSON」规则的目录。
3. 若 Scope=`SUBSET`：仅保留用户点名的 `<code>`。
4. 得到有序列表 `TARGETS[]`（建议字典序，便于核对）。

**完成判据**：`TARGETS[]` 非空（除非用户只要改 `en`，该类任务不在本协议默认范围内）。

---

## 阶段 4 — 生成译文

**输入**：主语言中每个待译 key 的英文 value；Policy；`TARGETS[]`。

**动作**：对每个 `<code> ∈ TARGETS`，对每个待译 key：

1. 根据英文与 `<code>` 语言习惯翻译。
2. 应用 Policy（如逐条核对 `.length`）。
3. 占位符与原英文一致。

**完成判据**：在清单或备注中能核对「每种语言 × 每个 key 均有一条非空译文（除非用户允留空）」。

---

## 阶段 5 — 写回仓库

**动作**：将阶段 4 的字符串**写入**对应 `language-package/<code>/<locale>.json` 的对应 key；不改动无关 key；不整体替换文件以免破坏格式——**优先局部替换**。

**完成判据**：磁盘上文件已更新；无 JSON 语法错误。

---

## 阶段 6 — 自检（Definition of Done）

在回复用户前**必须**核对：

1. [ ] 主语言 JSON 与用户需求一致。  
2. [ ] 所有 `TARGETS` 内文件 key 集合与主语言一致。  
3. [ ] Policy 中每条约束已执行（如有字数限制则抽查或逐条量 `length`）。  
4. [ ] 占位符未被翻译。  
5. [ ] 若宣称「完成」，则**不得**仍留有本任务 key 在任一目标语言中为 `""`（除非用户要求留空）。

---

## 无文件写权限时的退化路径（BATCH）

**仅当**用户声明无法写库或你只需要生成合并文件：

1. 输出单一合法 JSON：`{ "<code>": { "key": "译文", ... }, ... }`，顶层包含 Scope 内**全部** `<code>`。  
2. 提示用户运行：`npm run i18n:apply -- ./batch.json`（路径自定）。

**完成判据**：JSON 可被 `apply-i18n-batch.js` 接受（key 均存在于主语言）。

---

## 与脚本的对应关系（可选）

| 目的 | 命令 |
|------|------|
| 导出待译英文列表（伪 JSON 草稿） | `npm run i18n:queue` |
| 合并英文 JSON 进 `en` 并同步结构 | `node i18n-ai-queue.js --merge-en=./x.json` |
| 应用 batch 文件 | `npm run i18n:apply -- ./batch.json` |

智能体有能力时可直接改文件；脚本为可选加速器。
