# i18n AI 翻译（language-package）

## 全自动模式（默认，用户无需运行脚本）

本仓库已配置 `.cursor/rules/i18n-ai-auto.mdc`：**不要**让用户去跑队列/合并脚本；由 Agent 用工具完成闭环。

### 执行步骤（由上至下）

1. **读主语言**  
   打开 `language-package/en/` 下业务语言 JSON（文件名形如 `en_英语.json`；`i18n-` 前缀的 JSON 仅为辅助用途，若有则跳过，不作为主文案）。

2. **合并用户给的英文**  
   若用户粘贴或描述了新的英文键值：把相同 key 写入主语言 JSON（值用合法 JSON 字符串；保留占位符如 `{name}`）。

3. **结构对齐（可选但推荐）**  
   在项目根目录由 Agent 执行一次：`npm run i18n:sync-keys`  
   只会给其它语言补上缺失的 key（值为 `""`）并删掉主语言里已移除的多余 key。**用户无需操作。**

4. **枚举目标语言**  
   `language-package` 下除 `en` 外的每个子目录（且目录内存在业务 JSON）即一种目标语言；目录名即语言代码（如 `zh`、`ja`）。

5. **翻译并写回**  
   对每一种目标语言填入译文；保证 key 集合与英文主文件一致。  
   - **长度、简称、语气**：严格按用户在本轮对话里说的提示执行（例如「pleaseEnterBelow 各语言不超过 20 字符」）；**不要**从仓库里的独立规则文件读取（本项目不维护 `i18n-length-rules.json`）。  
   - 占位符逐字保留；品牌名/大小写按产品惯例。

6. **格式**  
   写回时维持该文件**现有**缩进风格，保证 JSON 合法。

### 禁止与例外

- **禁止**在默认流程里把「请运行 `npm run i18n:queue` / `apply-i18n-batch`」当作唯一交付；除非用户明确说只要 batch 草稿。  
- 若无法执行 `npm run i18n:sync-keys`，Agent 须手动对各语言 JSON 做同样的增删 key，再填译文。

---

## 何时加载本 Skill

- 用户粘贴英文 key-value，或带行尾逗号的伪 JSON 列表（来自 `i18n-ai-queue.js` 等）。  
- 用户修改 `language-package`、讨论缺失翻译或**在提示词里写了长度/风格要求**。  
- 用户提到全语言翻译或本 skill 名称。

---

## 默认：一次覆盖除 `en` 外全部语言

除非用户明确「只要 xx 语言」，否则应为每一种非 `en` 目录写入本次涉及的 key 的译文。

---

## 模板格式（英文源文案）

`i18n-ai-queue.js` 导出的是**伪 JSON**，每行仅 `key` + 英文值 + 行尾逗号，**不带** `,20` 等数字后缀；若需要字数上限，由用户在**同一句对话**里用文字说明，Agent 按提示执行。

示例：

```
{
  "generalSettings": "General Settings",
  "speakerVolume": "Speaker Volume",
}
```

用户在对话中可写：「speaker 那条译文各语言不超过 20 字符」——Agent 据此自检 `.length`。

---

## 翻译规则

1. **语言范围**：缺省为全部非 `en` 目录；单一语言时收窄。  
2. **占位符**：`{name}`、`{0}`、`%s` 等不得译改或删除。  
3. **长度与风格**：**仅**依据用户本轮提示词；未说明则无硬性字数，UI 文案仍宜简洁。  
4. **标点与空格**：按目标语言习惯；勿在字符串首尾多留无意义空格。

---

## 可选：离线条（CI、或无 Agent 写库权限时）

1. `npm run i18n:queue`（或 `--merge-en` / `--out`）  
2. 将输出交给模型时，**在同一提示里**写明长度等约束  
3. `npm run i18n:apply -- ./batch.json`

全自动模式下 Agent 应直接写各语言文件，一般不需要此路径。

---

## 示例

用户说：`pleaseEnterBelow` 的译文每种语言不超过 20 个字符（按 JavaScript `.length`）→ 每种语言生成后自检。

用户未提字数 → 正常翻译，避免冗长即可。
